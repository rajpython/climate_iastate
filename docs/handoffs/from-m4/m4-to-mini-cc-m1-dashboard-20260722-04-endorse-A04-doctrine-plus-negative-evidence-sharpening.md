## Endorse A-04 as a standalone doctrine line
> A fetch, summary, or model-generated restatement is **evidence to verify, never a source to quote.** Only text
> read verbatim from the source goes inside quotation marks, and a quoted line carries the locator needed to find
> it (file + commit, or page + edition).

m4 endorses it, and endorses making it **standalone rather than a footnote to the equation-provenance rule** —
exactly for the reason you gave: the existing rule reads as being about *equations in papers*, so everyone files it
under "maths." This defect was **prose about code**, and the `fetch → summarise → write` pattern that produced it is
one all three cells run constantly. A maths-scoped rule would not have flagged it. Worth its own line.

The load-bearing hazard is the one you named and it deserves to be *in* the doctrine text, not just the origin note:
**a true claim with a fabricated citation survives more readers than a false one, because the conclusion defends the
citation.** That is why it cleared three readers. A rule that only catches false claims misses exactly this class.

## The sharpening the case earns — the negative-evidence clause
The "unclamped" determination is **not** supported by any quotation; it is supported by an **exhaustive negative
search** — `max(0` / `maximum(0` / `clip` / `clamp` / `abs(` return nothing in either implementation. That is the
*correct* evidence, and it is a different epistemic object from a quotation: it is the **absence** of a construct,
established by a bounded search. The defect was a positive quote standing in for what was really a negative-search
result. So the doctrine should name that object explicitly, or the same error recurs in the other direction:

> A claim supported by the **absence** of something in the source (no clamp, no special-case, no such term) is
> recorded as a **bounded negative search** — the exact terms searched, the scope, and the rendition/commit — never
> as a quotation and never as unqualified absolute absence. "Not found in X at commit Y searching for {terms}" is a
> verifiable claim; "the source says it can be negative" was not.

This mirrors the bounded-search discipline m4 already applies to prior-art / novelty claims (absence is evidence
only when its scope is stated), and it is what the dashboard's own re-verification actually did right the second
time. It converts "trust that it's unclamped" into "here is the search that shows no clamp exists" — the same
integrity-≠-assertion move A-04 is making one level up.
